# Visual direction and art direction
- For new work: define product category, audience expertise, task density, emotional tone, existing brand constraints and comparative visual references. Distinguish screenshots/reference observations from original proposals.
- Specify typography hierarchy (families, available weights, line-height and sample content), spacing rhythm, grid/container strategy, surface treatment, color roles, iconography, illustration/image direction and responsiveness.
- Explore 2–3 materially different directions only when ambiguity/creative scope requires; evaluate against legibility, task speed, brand fidelity, accessibility, buildability and maintenance. Avoid arbitrary variety.
- Existing products: established style and approved decisions outrank trend-driven redesign. No invented highlight colors, shadows, patterns, dark cards or fonts.
- Real examples must be grounded in actual product/screens. Never pass generic demo UI as an approved brand application.
- Critic rubric: visual hierarchy, density, rhythm, coherent spacing, contrast, word wrap, semantic color use, state distinctions, purposeful imagery, personality without clutter.
- Keep a `design.md` style decision register: each decision has source, date, status (approved/proposed/rejected), rationale and impacted screens. Never treat speculative agent text as stakeholder approval.
- On screenshot review, identify concrete defects with coordinates/nodes and apply targeted edits, then recapture. Successful API call alone is not QA.
